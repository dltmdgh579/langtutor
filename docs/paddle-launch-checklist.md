# Paddle 운영 심사·출시 체크리스트

실제로 팔려면 남은 다섯 단계. 순서대로 진행한다.

## 1. 도메인 사기 (추천, 가장 먼저 정하기)

- [ ] 도메인 구입 (1년에 1~2만 원대, 예: rinrin.app)
- [ ] Render에 연결

이유:

- 지금 주소는 `langtutor-ufrw.onrender.com`이다. Paddle은 결제를 받을 도메인마다 승인을 따로 받아야 해서, 나중에 도메인을 바꾸면 심사를 다시 받아야 한다.
- Google 로그인을 "테스트"에서 정식 공개로 바꿀 때도 소유를 인증할 수 있는 도메인이 필요할 가능성이 크다. onrender.com은 내 도메인이 아니라 인증할 수 없다.

## 2. Paddle 운영 계정 (직접)

- [ ] `vendors.paddle.com`에서 운영 계정 가입 (sandbox와 별개 계정)
- [ ] 본인 인증: 여권이나 신분증 + 주소 증명 서류(영문 주민등록등본, 은행 거래내역서 등)를 Sumsub으로 업로드
- [ ] 정산 계좌: 은행 계좌(SWIFT 해외송금) 또는 Payoneer 등록
- [ ] 세금 서류: 미국인이 아니면 W-8BEN 작성

## 3. 사이트를 심사 기준에 맞추기 (코드)

- [ ] 가격 공개: 지금 배포된 사이트는 결제 키가 없어서 가격표가 숨겨져 있다. 심사자는 가격을 봐야 하므로 키가 없어도 가격이 보이게 고친다.
- [x] 문서 확인: 약관, 환불정책, 개인정보처리방침에 Rinrin 이름과 연락처가 보이는지 (이미 돼 있음)
- [ ] 로그인 없이 볼 수 있는지: 심사자가 로그인 없이 볼 수 있는 화면은 랜딩뿐이다. 기능 설명이 충분한지 다시 확인한다.
- [ ] Paddle의 Website approval 메뉴에서 도메인 제출 (보통 자동 승인, 수동 심사면 며칠)

## 4. 운영 결제 설정 (sandbox에서 한 걸 운영 계정에서 다시)

- [ ] 운영 가격 확정 (수수료 약 12% 감안)
- [ ] 운영 계정에서 만들기:
  - [ ] 상품과 가격
  - [ ] 클라이언트 토큰
  - [ ] 웹훅 대상: `https://<도메인>/api/paddle/webhook`
  - [ ] 기본 결제 링크
- [ ] Render 환경 변수: `PADDLE_ENV=production`과 운영 키 세 개를 넣고 재배포
- [ ] 실제 결제 테스트: 가장 싼 상품을 실제 카드로 한 번 사고 바로 환불해서 충전과 회수가 되는지 확인

## 5. 결제 외에 꼭 바꿔야 할 것

- [ ] Google 로그인 공개 전환: "테스트" 상태에서는 등록한 테스트 사용자만 로그인할 수 있다. Google Cloud 콘솔의 OAuth 동의 화면에서 앱을 "프로덕션"으로 바꾼다.
- [ ] 음성 API 유료 전환: Gemini 무료 등급은 상업 서비스에 맞지 않는다. 유료 키나 Grok으로 바꾸고, 개인정보처리방침의 "무료 등급으로 사용하는 동안" 문장도 고친다.
- [ ] Render 유료 플랜($7/월): 무료 플랜은 15분 동안 접속이 없으면 서버가 잠들어 첫 접속이 50초쯤 걸리고 웹훅도 늦어질 수 있다. 돈을 받기 시작하면 전환한다.
- [ ] 세금: 정산받은 돈은 다음 해 5월 종합소득세 신고 대상. 매출이 꾸준해지면 사업자등록.
